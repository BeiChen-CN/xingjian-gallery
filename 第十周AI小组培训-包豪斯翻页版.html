PART 01 / VIBE CODING03

网页上的一次点击，发生了什么？

HTML / 有什么

创建输入框、添加按钮和列表。没有它，页面缺少基本内容。

CSS / 长什么样

让输入框更宽、按钮变蓝、卡片留出间距；屏幕变窄时调整布局。

JavaScript / 怎么动

读取输入内容，点击后把文字放进列表；删除时移除对应任务。

三者协作：HTML 提供元素 → CSS 负责呈现 → JavaScript 响应操作。

VIBE CODING / 从问题出发04

案例：新生总是忘记要办的事

01

场景 / PROBLEM

小林刚入学，报名、领取资料、购买用品都要记。纸条容易丢，他想用一个网页随手记录。

最小可用版本：输入任务 → 添加到列表 → 完成后删除。

先完成这三步，再考虑筛选、提醒或跨设备同步。

VIBE CODING / 编写需求05

同一个想法，说清楚才好做

模糊的请求

“帮我做一个好看的网页。”

问题：用途、功能、交付方式都没有说明。AI 只能自行猜测。

清楚的请求

“为新生做待办清单，能添加和删除任务，空任务不添加，交付一个可以直接打开的 HTML 文件。”

用户、功能、边界和交付物都明确了。

现场提问：如果希望它在手机上也好用，还需要补充什么要求？

VIBE CODING / 可直接使用06

把需求交给 AI

请制作一个供新生记录学习任务的待办清单网页。需要输入框、添加按钮、任务列表和删除按钮；空内容不添加。页面适配电脑和手机。请把 HTML、CSS、JavaScript 写在一个 index.html 中，并告诉我如何保存、打开和测试。

观察：这段提示词写明了使用者、功能、空值处理、适配要求和交付方式。

VIBE CODING / 上机07

跟着做：让网页第一次跑起来

  1. 新建一个文件夹，例如 todo-demo；用文本编辑器新建 index.html。
  2. 把完整提示词发送给 AI；复制完整代码，粘贴到文件并保存为 UTF-8。
  3. 在文件管理器中双击 index.html，使用浏览器打开。
  4. 输入“领取校园卡”，点击添加；再点击删除，确认列表发生变化。
  5. 什么也不输入，再点添加；观察是否出现空任务。

如果打开后看到代码文字，检查文件名是否误存成 index.html.txt，并确认复制的是完整 HTML。

VIBE CODING / 测试08

别只看“能打开”，要试不同情况

操作期望结果如果不符合
输入“交报名表”并添加列表出现这条任务检查按钮与事件是否关联
空输入或只输入空格不新增空白任务检查是否先去除首尾空格
连续添加两条，再删第一条只删除第一条检查删除按钮对应的列表项
缩窄浏览器窗口文字和按钮仍可使用检查宽度、换行与移动端布局

选一项失败情形，记下操作步骤、预期结果与实际结果。

VIBE CODING / 排错对话09

出现问题时，怎样继续提问？

我在浏览器打开了 index.html，输入“交报名表”后点击添加，列表没有变化。预期是出现一条任务。我把当前完整代码和控制台报错贴在下面。请先指出可能原因，再给出修改后的代码和验证步骤。

先描述现象，再贴相关代码或报错。修改后重新保存、刷新，并重复失败的操作验证。

VIBE CODING / 迭代10

让网页更好用：一次只改一件事

第一轮：完成状态

“保留添加和删除功能。为每条任务增加复选框，勾选后显示删除线。”

验证：勾选一条，其他任务是否保持原状？

第二轮：界面调整

“按钮使用蓝色，任务卡片之间留出间距；手机屏幕上输入框占满宽度。”

验证：改变窗口宽度，按钮是否仍可点击？

一次修改后先测试原有功能；满意后再提出下一个改动。

VIBE CODING / 版本管理11

为什么要留一个版本？

当新修改把原功能弄坏时，可以找到之前的工作状态。Git 为项目记录一次次变更。

先安装 Git，并在项目文件夹打开终端。首次提交如提示身份信息，按提示配置用户名和邮箱。

git init
git add index.html
git commit -m "完成待办清单初版"

依次完成：初始化 → 选择文件 → 提交版本。

GitHub 可用于托管项目与协作；Skills 可补充 AI 的任务方法；MCP 用于连接工具与数据，本次只需理解用途。

PART 02 / AIGC12

动画短片，先从一个小故事开始

故事题目：寻找教室

新生小林拿着地图站在校园路口，找不到教室。一位同学看见后主动带路，两人一起走进教室。

先回答三个问题

谁：小林和一位同学。
遇到什么：找不到教室。
结果如何：得到帮助并准时到达。

情节不必复杂；观众能看懂人物、问题和结果即可。

AIGC / 剧本13

从一句话，扩写成可拍的动作

只有结论

“小林迷路了，然后同学帮了他。”

缺少可见动作，画面生成时容易空泛。

加入可见动作

小林停在路口，低头看地图，又抬头望向两栋楼。同学走近，指向左侧教学楼。两人一起走过去。

讨论：怎样只靠画面让观众看出“小林很困惑”？可以从表情、动作和环境入手。

AIGC / 分镜14

把故事拆成三个可执行镜头

镜头画面 / 动作景别 / 运镜声音 / 字幕
01小林站在路口，低头看地图远景，缓慢推进校园环境声；“教室在哪？”
02同学走近，指向教学楼中景，固定镜头“跟我来。”
03两人走进教室，相视一笑中景，平稳跟随轻快音乐；“新的故事开始了”

这是教学示例。镜头数量与时长可根据故事调整。

AIGC / 提示词15

让生成工具知道，你要什么画面

主体

谁出现在画面中？

场景

在哪里？什么时间？

动作

正在做什么？

风格

动画、写实或插画？

镜头

远景、中景或推进？

先把角色与动作写清，再补充风格、构图和光线。根据实际工具支持情况调整。

AIGC / 提示词示范16

把分镜 01 写成提示词

短发新生小林，穿蓝色连帽衫、背白色双肩包，站在阳光下的大学校园路口，低头看地图，表情困惑。二维温暖动画风格，远景，镜头缓慢推进，柔和自然光。

检查生成结果：人物是否拿着地图？服装是否正确？校园路口是否清晰？画面的氛围是否符合故事？

AIGC / 角色一致性17

同一个人，怎样跨镜头保持一致？

做一张角色设定卡

姓名：小林
外观：黑色短发
服装：蓝色连帽衫
道具：白色双肩包
风格：二维温暖动画

每次生成都核对

  1. 在后续镜头重复关键特征。
  2. 工具支持时，使用同一张角色参考图。
  3. 检查发型、衣服、背包和整体画风。
  4. 挑选最接近设定的素材，再修改偏差。
AIGC / 上机18

课堂练习：从分镜到一个素材

  1. 用两三句话写清故事的开头、经过、结尾。
  2. 参照示例，写出至少三个镜头的画面、动作和声音。
  3. 制作主角设定卡，写清发型、服装、道具和画风。
  4. 选择一个镜头，按主体、场景、动作、风格、镜头写提示词。
  5. 使用现有图像或视频生成工具，生成至少一个镜头素材。
  6. 与分镜和角色卡逐项对照，写下一处需要修改的地方。

可按现场已有工具操作；先确认素材使用条件，提示词中避免输入密码、密钥和他人隐私。

AIGC / 迭代19

画面不对，具体改哪一句？

问题：主角衣服变了

修改：明确写“蓝色连帽衫、白色双肩包”；工具支持时加入角色参考图。

问题：看不出在找路

修改：加入“低头看地图，再抬头望向教学楼，眉头微皱”。

问题：场景太拥挤

修改：明确“校园路口，小林位于画面中央，背景行人较少”。

问题：镜头太乱

修改：先尝试固定镜头或缓慢推进，再检查动作是否清晰。

AI LAB / 展示与讨论21

展示作品时，讲清这三件事

你做了什么？

展示网页的主要操作，或播放故事片段。

遇到了什么？

指出一个具体问题，例如按钮无响应或角色服装变化。

怎样改好的？

展示一次提示词或代码的修改，并说明如何验证。

作品不必一步到位，重要的是知道下一步怎么改。
