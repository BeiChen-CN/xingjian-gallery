PART 01 / VIBE CODING03

Vibe Coding 是什么？

用自然语言表达意图

把想要实现的功能、外观与限制告诉 AI，由 AI 协助编写或修改代码。

人的工作仍然重要

确定需求、选择方案、运行程序、判断结果并处理问题。是否可用，要通过实际操作确认。

不要求一开始记住全部语法；先理解网页各部分的作用和它们如何配合。

WEB / 前端边界04

前端页面能做什么？

页面内完成

浏览器可以显示内容、响应点击、修改当前页面；单文件作品适合学习和展示。

需要额外条件

跨设备同步、多人共享或发送消息通常需要后端服务；仅有 HTML 文件不会自动具备这些能力。

保存与刷新

页面上的临时状态可能在刷新后消失；要保留数据，必须设计存储方式并测试。

网络依赖

引用在线字体、图片或脚本时，断网可能影响效果。交付时要检查依赖和打开环境。

WEB / 基础结构08

HTML、CSS、JavaScript 分别做什么？

HTML / 结构

定义页面中的标题、文字、图片、链接、按钮和表单，并组织它们之间的层次。

CSS / 样式

决定颜色、字体、大小、间距和排列方式，也负责适配不同屏幕尺寸。

JavaScript / 行为

响应点击与输入，读取和修改页面内容，让界面随用户操作发生变化。

浏览器共同处理结构、样式和脚本；解析、样式计算与脚本执行可能交错进行。

WEB / 一只小鸟01 / HTML
01 / HTML

先有结构

HTML 像小鸟的轮廓和部件

组织标题、文字、图片与按钮，确定页面里有什么，以及它们的关系。

这是帮助入门的类比，不是绝对规则：实际网页中，结构、外观与行为会协同工作。

WEB / 一只小鸟02 / CSS
02 / CSS

再添外观

CSS 像小鸟的色彩和样子

为同样的结构设置颜色、字体、大小与布局，让内容更容易被看见。

这是入门类比，并非绝对规则：CSS 也能实现部分视觉动画。

WEB / 浏览器12

浏览器怎样把文件变成页面？

读取文件

浏览器接收 HTML 文件及其引用资源。

建立结构

解析标签，形成可供程序访问的页面结构。

计算样式

根据 CSS 确定元素的外观与位置。

处理交互

运行脚本，监听操作并更新内容。

以上是简化示意；解析、样式计算、渲染和脚本执行可能交错。页面显示后仍需测试交互、屏幕适配和边界情况。

WEB / 结构与语义13

好的 HTML 不只是把内容放上去

用层次表达信息

页面标题、章节标题、正文和列表各有不同作用。明确层次后，阅读和后续维护都更容易。

用合适的元素表达用途

跳转使用链接，触发操作使用按钮，填写信息使用带标签的表单控件，有助于键盘操作与辅助技术识别。

写需求时可以要求：结构清晰、控件有可理解的名称、支持键盘操作。

WEB / 样式与布局14

CSS 决定信息怎样被看见

视觉层级

通过字号、粗细和颜色区分标题、正文与提示，先让人看到最重要的信息。

空间与对齐

使用间距、对齐和分组建立秩序，避免内容拥挤或各部分关系不清。

响应式布局

让内容随屏幕宽度调整，确保文字可读、控件可点、页面无需横向拖动。

WEB / 交互逻辑15

交互可以拆成四个环节

触发

用户点击、输入或选择，浏览器接收到操作。

读取

程序获取当前输入或页面状态。

判断

根据条件决定是否执行，以及如何处理异常输入。

更新

改变页面内容，并让用户看见操作结果。

排查功能时，可以沿这条链路逐步检查：事件是否触发、数据是否正确、判断是否通过、界面是否更新。

VIBE CODING / 功能拆解16

把需求拆成可验证的功能

列出操作

写出用户能够执行的动作，以及每个动作对应的页面反馈。

补全状态

说明初始、输入中、成功与失败时页面分别显示什么。

确定边界

明确无内容、重复操作和异常输入应如何处理，避免只描述理想流程。

划定优先级

先完成必须具备的功能，再增加视觉细节和可选功能；每完成一项就进行检查。

VIBE CODING / 需求17

写需求时，先确定四类信息

目标与受众

谁会使用？他们希望完成什么？页面的主要用途是什么？

功能与规则

需要哪些操作？输入无效时如何处理？每一步应出现什么反馈？

视觉与适配

说明风格、信息层次、设备尺寸与可读性要求。

交付与验证

说明文件形式、运行方式、使用说明和需要检查的功能。

VIBE CODING / 提示词18

提示词不是越长越好，而是信息要完整

先给背景，再提任务

说明使用对象与具体目标，让 AI 理解作品服务于什么需求。

把要求拆成可检查的条目

分别列出功能、页面结构、交互反馈和限制条件，避免只使用抽象形容词。

约定输出形式

说清需要完整文件还是局部修改，以及运行和使用说明应包含什么。

允许分轮完成

先完成主要功能；检查后，再提出样式、细节和体验方面的改动。

VIBE CODING / 修改策略19

怎样让一次修改更可控？

限定改动范围

说明需要调整的页面区域、交互和期望行为，并提醒 AI 保留已有功能。

要求解释变化

请 AI 说明修改的位置、理由和影响，并给出可以直接应用的完整内容或清晰补丁。

保存可回退版本

修改前保存已有版本；改动后确认文件保存成功，再刷新浏览器。

逐项回归测试

先测试新功能，再检查原有操作；出现问题时保留报错与重现步骤。

VIBE CODING / 文件操作20

从生成结果到可运行文件

  1. 为项目建立文件夹，明确文件名与保存位置。
  2. 将完整代码保存为 HTML 文件，确认扩展名和编码正确。
  3. 用浏览器打开文件；后续修改后保存并刷新页面。
  4. 如页面引用了其他文件，确认它们的位置和路径与代码一致。
  5. 检查功能、屏幕适配与文字显示，并记录发现的问题。

单文件网页将结构、样式和脚本放在同一 HTML 文件中，便于本次课程提交和打开。

VIBE CODING / 检查21

怎样判断网页是否完成？

功能

逐项操作控件，确认结果符合需求；检查空输入、重复操作及错误输入。

呈现

查看文字、颜色、对齐和间距，改变窗口大小，确认内容没有被遮挡。

使用

检查按钮名称和反馈是否清楚，尝试使用键盘操作，确认使用说明完整。

每次改动后重测主要功能；修复一处问题时，也要留意其他部分是否受到影响。

VIBE CODING / 排错22

遇到错误，给 AI 哪些信息？

重现过程

说明打开了什么、执行了哪些操作，以及问题是否每次都发生。

预期与实际

分别写清楚本来希望发生什么，以及现在实际看到了什么。

相关上下文

提供有关代码、报错信息和使用环境；注意移除密码、密钥和隐私数据。

验证修复

请 AI 解释原因和修改位置；保存后重复原步骤，再检查其他主要功能。

VIBE CODING / 开发者工具23

用浏览器开发者工具定位问题

打开工具

在浏览器中按 F12；如快捷键不同，可从浏览器菜单打开开发者工具。

查看 Console

控制台显示脚本错误和日志；记录报错文本、文件名与行号，再结合操作步骤分析。

检查页面元素

使用元素面板查看标签、文字和生效的样式；临时调整可用于验证想法，刷新后通常会还原。

反馈给 AI

整理预期、实际现象、完整报错及相关代码；先删除账号密码、令牌和个人信息。

VIBE CODING / 版本24

Git 与项目版本

为什么记录版本？

版本记录保存项目在不同阶段的变化，便于查看修改、比较差异和回到已记录的状态。

提交前先确认保存了文件，并知道当前位于哪个项目文件夹。

基本工作顺序

  1. 在项目目录初始化仓库。
  2. 检查哪些文件发生了变化。
  3. 将需要记录的文件加入暂存区。
  4. 提交并写清这一版完成了什么。

Git 是版本管理工具；GitHub 可以托管项目并支持协作。首次使用 Git 可能需要配置提交者身份。

VIBE CODING / 实际操作25

Git：记录一次可恢复的工作进展

初始化仓库

打开项目文件夹中的终端，执行 git init；这会在当前目录创建 Git 仓库。

查看状态

执行 git status，确认当前目录和待记录文件；检查是否包含无需提交的敏感信息。

加入并提交

执行 git add index.html，再执行 git commit -m "完成初版"；提交前先保存文件。

确认记录

执行 git log --oneline 查看提交；如首次提交提示身份未配置，按 Git 提示配置后重试。

这些命令要求设备已安装 Git。文件名应与项目中的实际文件一致。

VIBE CODING / 扩展认识26

Skills 和 MCP 在协作中扮演什么角色？

Skills / 任务方法

把完成某类任务的步骤、知识或约定组织起来，帮助 AI 按特定方法工作。

MCP / 工具连接

为 AI 连接外部工具和数据提供一种通用协议，让其在支持的环境中调用相关能力。

本次以认识用途为主；具体功能取决于使用的工具与环境，不要求现场配置。

PART 02 / AIGC27

AIGC 如何进入内容制作？

AIGC 指使用生成式人工智能辅助产生文字、图像、音频或视频等内容。

生成之前

确定表达主题、受众、风格和成品形式；准备脚本、角色设定和素材要求。

生成之后

筛选结果、检查一致性、修改不足，再通过剪辑与声音组织成完整作品。

AIGC / 故事28

故事梗概要交代什么？

人物与处境

说明主要人物是谁、身处什么环境，以及希望达成什么目标。

变化与行动

明确发生了什么变化，人物如何作出行动，以及事情怎样推进。

结果与主题

交代事情如何结束，以及希望观众感受到或理解的内容。

梗概用来确定整体方向；脚本进一步写清动作、画面、对白与声音。

AIGC / 创作规划29

动手前，先把作品边界定下来

观众与目的

明确作品面向谁，希望观众理解或感受什么，确保内容选择服务于目标。

长度与形式

确定目标时长、画幅比例和输出形式；检查使用平台对画面与文件格式的要求。

资源与条件

盘点可用工具、素材来源和制作时间；估计各镜头生成与调整所需工作量。

统一的视觉设定

确定画风、色彩、光线和角色外观，记录成简短设定，供各镜头复用。

AIGC / 脚本30

从故事梗概写到可执行的脚本

描述可观察的内容

明确人物的动作、表情和场景变化，让画面承担一部分叙事信息。

组织信息顺序

安排开头、发展与结尾，保证观众能理解人物、事件及其关系。

补充对白与声音

标明需要说的话、环境声与音乐，并考虑它们与画面的配合。

控制内容规模

根据目标时长和制作条件取舍情节，给关键动作留出呈现时间。

AIGC / 分镜31

分镜：把脚本拆成可以制作的镜头

每个镜头要交代

镜头编号、人物和场景、画面动作、景别与运镜、对白或声音，以及预计时长。

镜头之间要衔接

检查空间位置、动作方向、人物外观与前后信息是否连续，避免观众看不懂发生了什么。

分镜是制作计划：帮助确定每个镜头需要哪些素材，并为后续生成和剪辑提供依据。

AIGC / 分镜制作32

分镜表怎样真正用于制作？

一行对应一个镜头

为每个镜头记录编号、预计时长、画面内容、角色动作和背景。

交代视听信息

明确景别、镜头运动、对白、音效与字幕；没有某项时可留空。

关联生成素材

记录需要的角色参考、场景参考与素材文件，便于生成、筛选和替换。

在剪辑前检查

按顺序读一遍镜头；核对事件顺序、人物位置与时间总长是否符合目标。

AIGC / 镜头语言33

景别与运镜影响观众看到什么

景别

远景展示环境和人物位置；中景关注动作；近景与特写突出表情或细节。

构图

安排主体在画面中的位置、视线方向和前后关系，让观众知道该看哪里。

运镜

固定、推进或跟随等方式会改变观看节奏；选择应服务于内容和情绪。

制作时先确定画面需要传递的信息，再选择景别和运动方式。

AIGC / 提示词34

生成画面时，需要描述哪些信息？

主体与动作

交代画面中有哪些主体、它们的外观特征，以及正在发生的动作。

场景与气氛

描述环境、时间、光线、色彩与情绪，减少画面方向的歧义。

风格与画面

说明整体视觉风格、景别、构图和镜头运动等要求。

调整与筛选

生成后对照分镜检查；找出偏差，修改有关描述，再选择合适素材。

AIGC / 迭代方法35

一次只调整影响结果的关键条件

先选检查重点

对照分镜，从主体、动作、场景、风格和镜头中找出最影响理解的问题。

修改对应描述

明确要改变的内容与保留的内容，避免每次同时改动太多条件。

对照版本筛选

保留可用结果和对应提示词，比较修改前后差异，再决定是否继续调整。

承认工具差异

不同工具支持的参考图、参数和生成方式不同；以实际界面和生成效果为准。

AIGC / 一致性36

如何让同一角色贯穿多个镜头？

生成前：建立设定

记录角色的外观、发型、服装、道具、比例与画风，形成可复用的角色设定。

生成时：保持关键特征

在各镜头中持续描述固定特征；工具支持时，可以使用同一角色参考素材。

生成后：逐镜头检查

比较面部、服装、道具和风格，筛选一致的画面；偏差明显的素材重新调整。

关注场景连续性

同时检查空间、光线、人物位置和动作方向，保持前后镜头衔接。

AIGC / 输出37

从素材到短片：还需要哪些工作？

筛选

按分镜检查画面与角色，保留符合要求的素材。

排列

按叙事顺序组织镜头，调整每段停留时间。

声音

根据内容添加对白、环境声、音乐和字幕。

检查

完整播放，确认画面衔接、声音和字幕可读。
